# P5-1 UI 登录态设计（2026-09-24）

## 背景 / 目标

- 现状证据：`api/auth.go` 中间件返回 401（basic/token 两种方案，`crypto/subtle` 常量时间比较）；但 `web/static/` 全仓 **0 处** 401/login 处理（grep 实证）。
- 缺口：启用鉴权（`auth.type=basic|token`，Docker/公网默认开启）后，UI 所有请求 401 → 页面报错白屏，**无登录入口、无凭据附加**。
- 目标：启用鉴权后 UI 可登录使用；401 自动跳转登录页；凭据持久化。

## 组件与接口

- `web/static/app/auth.js`（新）：登录态管理纯函数模块
  - `getAuth()` / `setAuth(cred)` / `clearAuth()`：localStorage 读写（key `dm.auth`）
  - `authHeader()`：返回 `Authorization` 头（basic 用 base64(username:password)，token 用 `Bearer <token>`）
  - `isAuthed()`：凭据存在
- `web/static/app/api.js`（改）：fetch 封装统一附加 `authHeader()`；401 响应触发 `onUnauthorized` 回调
- `web/static/index.html`（改）：内嵌登录视图（Vue，`#login-view`，初始 hidden）——用户名/密码 + token 两种模式；登录成功回调校验（POST /api/auth/verify 或 GET 受保护端点）
- `api/server.go`（改）：新增 `POST /api/auth/verify`（带凭据请求返回 200/401，供前端验证凭据）

## 数据流

1. 页面加载 → `api.js` 首个请求带 localStorage 凭据
2. 401 响应 → 触发 `onUnauthorized` → 显示 `#login-view` 遮罩
3. 用户提交凭据 → `verifyAuth(cred)`（带 Authorization 请求 /api/auth/verify）→ 200 则 `setAuth` + 隐藏遮罩 + 刷新数据
4. 登出按钮 → `clearAuth` + 显示登录页

## 错误处理

- 凭据错误：401 → 登录页内提示「凭据无效」不清除旧凭据
- 网络错误：非 401 的失败不触发登录流程，保持原错误提示
- 服务端未启用鉴权（auth.type=none）：verify 恒 200，登录页不出现

## 测试 + 变异点

- node --test：`auth.test.js` 覆盖 setAuth/getAuth/authHeader（basic base64 正确、token Bearer 正确、clear 后 isAuthed false）
- Playwright e2e：`test/playwright/specs/auth.spec.ts`
  - 服务端开启 auth（fixture 传 DM_AUTH_ENABLED + 用户名/密码）→ 未登录访问 → 登录页出现
  - 输入正确凭据 → 登录成功 → dashboard 数据可见
  - 输入错误凭据 → 提示且停留登录页
  - 登出 → 回到登录页
  - **变异点**：api.js 不附加 Authorization → e2e 红；401 不触发 onUnauthorized → e2e 红；authHeader basic 编码错误 → 单测红

## 片划分

- P1（核心）：auth.js + api.js 头附加 + 401 拦截 + 登录视图 + verify 端点
- P2（打磨）：登出、凭据过期提示、remember me
- P3（体验）：Docker 部署时首次启动提示设置凭据

## 风险与零回归

- 默认（auth.type=none）行为零变化：verify 恒 200、无 Authorization 头附加不影响无鉴权服务
- localStorage 凭据仅存前端，服务端无新凭据存储面
- 后端新端点只读校验，不引入写路径
